# Polish (Milestone 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Animations, WebAudio sounds with a mute toggle, quick-chat, reconnect handling in the UI, a PWA manifest, and the mobile rules audit.

**Architecture:** Every effect is driven by the `GameEvent`s and `chat` messages the server already sends. Pure mappers (`sfxFor`, `animationFor`, `connectionBanner`, `phraseText`) are tested in node; DOM/CSS/WebAudio code on top is verified by hand.

**Tech Stack:** Vanilla DOM, CSS animations, WebAudio (generated sounds, no audio files), TypeScript strict, Vitest (node).

**Spec:** `CLAUDE.md` §4 ("Capote-like feel", "Responsive/mobile rules"), §5 milestone 7. **Depends on:** the networking, lobby UI, table UI and truco-flow UI plans.

## Global Constraints

- Sounds are generated with WebAudio (no copied assets). The `AudioContext` is created or resumed only after a user gesture (mobile browsers block it otherwise). Mute state is persisted in `localStorage`.
- Animations: card slides to the table, trick sweeps toward the winner, chair wiggles on your turn, screen shake and flash on truco calls. Respect `prefers-reduced-motion` (disable shake and sweep).
- Quick-chat phrases, exact pt-BR text: "Bora!", "Tá fraco", "Truco, ladrão!", "Esse é meu", "Rapaz...". Ids are `QUICK_PHRASES` from `shared/protocol.ts`: `bora`, `fraco`, `truco_ladrao`, `meu`, `rapaz`.
- Reconnect: the token is in `localStorage`; the UI shows connection state and a player who dropped is visibly marked.
- PWA: manifest only, `display: standalone`, `orientation: portrait`. No service worker (a LAN `http://` origin is not a secure context, so it would never register).
- Mobile: `<meta viewport ... viewport-fit=cover>`, touch-first, min tap target 44px, `touch-action: manipulation`, no pull-to-refresh or double-tap zoom, portrait, tested at 360×640 and desktop.
- No new dependencies. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; each task ticks its `FEATURES.md` boxes.

## Review Focus

1. The first tap on a fresh page unlocks audio; no console error or exception when `AudioContext` is unavailable. [Task 1]
2. With mute on, no sound plays and no `AudioContext` work is scheduled; the setting survives reload. [Task 1]
3. Rapid event bursts (a whole trick resolving) do not leave cards stuck mid-animation or double-rendered. [Task 2]
4. Spamming a quick-chat button cannot flood the room: the client limits itself to one phrase per second and the server rate limiter still applies. [Task 3]
5. A bubble or chat for a player who then disconnects does not break the layout; reconnect restores the snapshot with no stale "reconnecting" banner. [Task 4]

**Interfaces:**

- Produces from `sfxModel.ts`: `type SfxName = 'slap' | 'knock' | 'sweep' | 'win' | 'lose' | 'chime'`; `sfxFor(event: GameEvent, myTeam: 0 | 1): SfxName[]` — `card_played` → `['slap']`; `truco_called` → `['knock']`; `truco_answered` → `['chime']`; `trick_won` → `['sweep']`; `match_won` → `['win']` or `['lose']` by `myTeam`; others → `[]`.
- Produces from `sfx.ts`: `interface Sfx { unlock(): void; play(name: SfxName): void; startAmbience(): void; setMuted(muted: boolean): void; readonly muted: boolean }` and `createSfx(storage?: Pick<Storage, 'getItem' | 'setItem'>, ctxFactory?: () => AudioContext): Sfx`. Slap = short filtered noise burst; knock = two low sine thumps (≈ 90 Hz) 120 ms apart; crowd ambience = looping band-passed noise at low gain with slow modulation. When `ctxFactory` throws or `AudioContext` is undefined, all methods are no-ops.
- `muteButton.ts`: `renderMuteButton(sfx: Sfx): HTMLElement` — 44px icon button (🔊/🔇), `aria-pressed`.

- [ ] **Step 2: Run** `npx vitest run client/audio`. Expected: FAIL.
- [ ] **Step 3: Implement** the three files. `app.ts` calls `sfx.unlock()` on the first `pointerdown` and `startAmbience()` once a game starts.

- Modify: `client/ui/table.ts`, `client/app.ts`

**Interfaces:**
- Consumes: `GameEvent`; `relativeIndex`, `anchorFor` from `client/ui/layout.ts`.
- Produces from `animationModel.ts`:
  - `type Animation = { kind: 'slide'; anchor: Anchor } | { kind: 'sweep'; toward: Anchor | null } | { kind: 'shake'; strength: 1 | 2 | 3 }`
  - `animationFor(event: GameEvent, mySeat: Seat, mode: GameMode): Animation | null` — `card_played` → slide from the player's anchor; `trick_won` → sweep toward the anchor of `event.leader` (the seat that leads next; confirm in `engine/tricks.ts` that this is the seat of the winning card, and for a tied trick `winner: null` use `toward: null` so the cards fade at the centre); `truco_called` → shake with strength 1/2/3 for stake 3 or 6 / 9 / 12; others `null`.
- Produces from `animations.ts`: `play(animation, table: HTMLElement): void` applying CSS classes (`.slide-from-<anchor>`, `.sweep-to-<anchor>`, `.shake-1..3`) and removing them on `animationend` or after a 1 s safety timeout. `setChairTurn(table, activeSeat)` toggles the wiggle class (`.turn`) on the active chair only, and only for the viewer's own chair a stronger wiggle. A flash overlay on truco calls.
- Everything respects `@media (prefers-reduced-motion: reduce)` (no shake/sweep/wiggle).
