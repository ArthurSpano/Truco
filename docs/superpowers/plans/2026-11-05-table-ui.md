# Table UI (Milestone 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the boteco scene, per-mode seating layouts for 2, 4 and 6 players, the player's hand with tap-to-play, played cards, vira with highlighted manilha, hand value, score (Nós × Eles) and trick pips.

**Architecture:** Same pattern as the lobby: pure view-model modules (seat geometry, table model, hand-fan math, selection state machine) with node tests, and thin DOM renderers on top. The scene (table, chairs, neon sign, tiled floor) is CSS plus inline SVG, no canvas. The renderer reads only `GameView` and `RoomState`.

**Tech Stack:** Vanilla DOM, CSS, inline SVG, TypeScript strict, Vitest (node).

**Spec:** `CLAUDE.md` §4 "Scene" and "Layout by mode", §5 milestone 5. **Depends on:** the networking plan and the lobby UI plan (`client/app.ts`, `AppState`, `GameSocket`).

## Global Constraints

- Client never imports `engine/` or `server/`; it renders snapshots. Derive "relative seat" and teams locally (`team = seat % 2`).
- Layouts (portrait phone): 2p you bottom, opponent top; 4p you bottom, partner top, opponents left and right; 6p you bottom, hexagon around the table, teammates alternate seats. Turn order is counter-clockwise, so from the bottom the next seat is on the right.
- Your hand fans at the bottom, large tappable cards, tap to select then tap again (or drag) to play, with a face-down toggle. Other players show card backs.
- Centre: played cards, the vira with the manilha highlighted, current hand value, score for both teams as *Nós* × *Eles*, trick-result pips.
- Draw with CSS/SVG, keep it light for phones. Original art; no real beer brands or logos. Copy in pt-BR.
- Min tap target 44px, `touch-action: manipulation`, test at 360×640 and desktop.
- No new dependencies. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; each task ticks its `FEATURES.md` boxes.

## Review Focus

1. A 6-player table at 360px wide: seat tags and names do not overlap or overflow; a 16-character name is truncated with an ellipsis. [Task 3]
2. Face-down cards on the table and in `tricks` show a back, never a face (the view has no `card` for them). [Task 2, Task 4]
3. Tapping a card when it is not your turn does nothing (no message sent); `view.actions.play` gates it. [Task 5]
4. A view where `turn` is `null` (match over) or the hand has 0 cards renders without throwing. [Task 4]
5. Tricks tied (`winner: null`) show a neutral pip, not a team colour. [Task 4]

**Interfaces:**
- Consumes: `GameView`, `RoomState`, `layout.ts`, `card.ts`, `scene.ts`.
- Produces from `tableModel.ts`:
  - `type Pip = 'won' | 'lost' | 'tied' | 'pending'`
  - `interface SeatModel { seat: number; anchor: Anchor; name: string; team: 0 | 1; mine: boolean; partner: boolean; connected: boolean; active: boolean; cardCount: number; cards: Card[] | null }`
  - `interface TableModel { seats: SeatModel[]; us: number; them: number; value: number; vira: Card; manilha: Rank; pips: Pip[]; trick: { anchor: Anchor; card: TableCard }[]; maoDeFerro: boolean; over: { won: boolean } | null }`
  - `tableModel(view: GameView, room: RoomState): TableModel` — `us`/`them` are the viewer's team score first (Nós × Eles) regardless of seat parity; `pips` always has 3 entries (finished tricks mapped relative to the viewer's team, then `pending`); a seat's name comes from the `PlayerInfo` whose `seat` matches; `active` is `view.turn === seat`.
- Produces from `table.ts`: `renderTable(model: TableModel, handler: { onPlay(cardId, faceDown): void }): HTMLElement` composing scene, chairs, card backs fanned by `cardCount` beside each opponent, the centre (trick cards at their seat's anchor side, vira with `.manilha` marker, `Valendo N` badge, `Nós X × Y Eles` scoreboard, pips). The hand is added in Task 5.

### Task 5: Hand fan and card play

**Files:**
- Create: `client/ui/handFan.ts`, `client/ui/hand.ts`
- Test: `client/ui/handFan.test.ts`
- Modify: `client/ui/table.ts` (mount the hand at the bottom)
- Modify: `FEATURES.md` (tick "Hand fan, card selection and play")

**Interfaces:**
- Consumes: `GameActions`, `Card` from `shared/types.ts`; `renderCard` (Task 2).
- Produces from `handFan.ts`:
  - `fanLayout(count: number): { angle: number; offsetX: number; lift: number }[]` — symmetric fan, at most 10° between neighbours, empty for 0.
  - `interface HandState { selected: string | null; faceDown: boolean }`
  - `type HandAction = { kind: 'tap'; cardId: string } | { kind: 'toggle_face_down' } | { kind: 'sync'; cardIds: string[]; actions: GameActions }`
  - `handReduce(state: HandState, action: HandAction): { state: HandState; play: { cardId: string; faceDown: boolean } | null }` — first tap selects; tapping the selected card returns `play` (only if `actions.play` or `actions.playFaceDown` allows it; `faceDown` only if `playFaceDown`); `sync` drops a selection whose card left the hand and forces `faceDown: false` when `playFaceDown` is false. Keep the last `GameActions` in the state so `tap` can check it.
- Produces from `hand.ts`: `renderHand(cards: Card[], manilha: Rank, actions: GameActions, onPlay: (cardId: CardId, faceDown: boolean) => void): HTMLElement` — fanned cards, selected card lifted, a "Virada" toggle (≥ 44px) shown when `actions.playFaceDown`, dragging a card upward past a threshold also plays it (pointer events), cards `aria-disabled` when it is not your turn.

- [ ] **Step 1: Failing tests** for `handFan.ts`: `fanLayout(0)` is `[]`; `fanLayout(3)` angles are symmetric (`a[0] === -a[2]`, `a[1] === 0`); consecutive angles differ by ≤ 10°; first tap selects with `play: null`; second tap on the same card returns `play` with `faceDown: false`; tap on another card moves the selection; with `actions.play === false && playFaceDown === false` a double tap returns `play: null`; with `toggle_face_down` then double tap and `playFaceDown: true` returns `faceDown: true`; with `playFaceDown: false`, toggling has no effect; `sync` clears a selection no longer in `cardIds`.
- [ ] **Step 2: Run** `npx vitest run client/ui/handFan.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** `handFan.ts` and `hand.ts`; `table.ts` passes `onPlay` that sends `{t:'play_card', cardId, faceDown}`.
- [ ] **Step 4: Verify.** `npm run check`; in a two-window game, tapping a card out of turn sends nothing (watch the server console or the Network tab), double tap plays it, and from trick 2 the Virada toggle appears and plays a back-facing card on the table.
