# Stretch (Milestone 8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bots for empty seats (and takeover for dropped players), optional mkcert HTTPS, per-match stats, and a README with an architecture diagram.

**Architecture:** Bots are server-side players that look exactly like human players to `Room` (they have a player id and a seat) but their intents come from `server/bots.ts`, a pure function over the bot's own `GameView`. A `BotRunner` watches room changes and schedules a bot move after a short human-like delay. HTTPS is opt-in through certificate files; the HTTP path is unchanged. Stats are counted from the public events the room already produces.

**Tech Stack:** Node `https`, `ws`, Vitest, existing engine helpers. No new dependencies (mkcert is an external CLI the user installs).

**Spec:** `CLAUDE.md` §1 (optional `mkcert`), §2 (optional bots, bot takeover after 60 s), §5 milestone 8, §6 (README contents). **Depends on:** the networking plan (`Room`, `net.ts`) and, for the stats screen, the table UI plan.

## Global Constraints

- Bots see only their own `GameView` (no peeking at other hands): `chooseBotIntent` takes a `GameView`, never `GameState`.
- Keep bots simple: play the lowest card that wins the trick, otherwise the lowest card; accept truco when the hand is strong; never call truco unprompted beyond a simple strong-hand rule; run otherwise.
- HTTPS is optional: the server starts on plain HTTP when no certificate is configured. Certificate and key files (`*.pem`) are git-ignored already; never commit them.
- State stays in memory; no databases or external services.
- README must document: how to run on a phone hotspot, the firewall note, the client-isolation gotcha (already present: keep them accurate), plus the networking and architecture decisions and a diagram.
- Ask before adding any dependency. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; each task ticks its `FEATURES.md` boxes.

## Review Focus

1. A bot never acts out of turn, never acts twice for one state, and stops acting when the match is over. [Task 2]
2. A human who rejoins after takeover gets their seat back and the bot stops; the hand they were dealt is unchanged. [Task 3]
3. HTTPS with a missing or unreadable key file fails with a clear pt-BR message and exits, instead of silently serving HTTP. [Task 4]
4. The QR code and printed URLs use `https://` when TLS is on, and `ws` becomes `wss` in the client automatically. [Task 4]
5. Stats never include hidden information (only public events), and reset for a new match. [Task 5]

### Task 1: Bot decision function

**Files:**
- Create: `server/bots.ts`
- Test: `server/bots.test.ts`

**Interfaces:**
- Consumes: `GameView`, `GameIntent`, `Card` from `shared/types.ts`; `compareCards` and `isManilha`-style helpers from `engine/deck.ts` (read the exact exports first; the server may import the engine); `legalIntents` from `engine/simulate.ts` as the source of legal intents.
- Produces: `chooseBotIntent(view: GameView): GameIntent | null` — `null` when `legalIntents(view)` is empty. Rules in order: (1) answering a truco: `accept` when hand strength ≥ 2 (strength = count of manilhas plus count of `3` or `2` ranks in the bot's cards), `run` otherwise, never `raise`; (2) mão de onze decision: play when strength ≥ 2 else run; (3) mão de ferro: `play_blind` slot 0; (4) playing: if a card in hand beats the best card currently on the table (face-up cards only), play the lowest such card; otherwise the lowest card in hand, face down from trick 2 on when it cannot win; leading: play the highest card in trick 1 only if strength ≥ 2, else the lowest; (5) call `call_truco` only when strength ≥ 3 and it is allowed. Deterministic: no randomness.

- [ ] **Step 1: Failing tests** (build `GameView`s by hand or via `createGame` with a seed and `viewFor`): returns `null` when it is not the bot's turn and nothing is pending; with a vira making `3` the manilha... pick a concrete seeded game and assert the bot plays the lowest winning card when one exists; plays its lowest card when nothing wins; accepts a truco with two manilhas in hand and runs one with three low cards; never returns `raise`; in mão de ferro returns `{t:'play_blind', slot:0}`; every intent returned is in `legalIntents(view)` over 300 seeded random positions in each of modes 2, 4 and 6 (property-style loop using `engine/simulate.ts` `simulateMatch` with `chooseBotIntent` as the strategy source if it fits; otherwise step manually with `applyIntent`).
- [ ] **Step 2: Run** `npx vitest run server/bots.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** `chooseBotIntent`.
- [ ] **Step 4: Run** `npx vitest run server/bots.test.ts` and `npm run typecheck`. Expected: PASS, including 100 full bot-vs-bot matches per mode finishing without engine errors.
- [ ] **Step 5: Commit** (`Bots: decision rules`).
