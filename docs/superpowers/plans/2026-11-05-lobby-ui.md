# Lobby UI (Milestone 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phones can create a room, join by code, pick a seat, ready up, and see the LAN URL and QR in the lobby.

**Architecture:** The client is a thin renderer. A pure reducer folds `ServerMessage`s into an `AppState`; a `GameSocket` wrapper owns the WebSocket, token storage and reconnect; screens are plain DOM functions `(state, send) => HTMLElement`. All logic that can be pure (reducer, form validation, seat-slot model) lives in node-testable modules; DOM screens are verified by hand at 360×640 and on desktop.

**Tech Stack:** Vite, TypeScript, vanilla DOM and CSS. Vitest in the node environment (no jsdom: that would be a new dependency).

**Spec:** `CLAUDE.md` §2, §4 (responsive/mobile rules, pt-BR copy), §5 milestone 4. **Depends on:** the networking plan (`2026-11-05-networking.md`) being complete: `shared/protocol.ts` and the `/ws` endpoint.

## Global Constraints

- Client never imports from `engine/` or `server/`; it may import `shared/`.
- Copy in Brazilian Portuguese. Mobile-first: min tap target 44px (`--tap` in `base.css`), `touch-action: manipulation`, no hover-only UI, test at 360×640 and desktop.
- Client sends intents only and renders what the server sends. No client-side rule logic.
- Original art and names only; no brand logos.
- Do not add dependencies. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; each task ticks its `FEATURES.md` boxes in the same commit.

## Review Focus

1. A room code typed in lowercase, with spaces, or pasted with a URL fragment still joins. [Task 3]
2. Server `error` messages (room full, seat taken, room not found) appear as visible text in pt-BR, not silently. [Task 1, Task 3]
3. Page reload in a lobby or game reconnects with the stored token instead of dropping the player; a stale/rejected token is cleared and the home screen shows. [Task 2]
4. The socket closing while on the home screen (server restart) does not leave a dead "Criar sala" button. [Task 2]

### Task 2: Socket wrapper with token storage and rejoin

**Files:**
- Create: `client/net/socket.ts`, `client/net/tokenStore.ts`
- Test: `client/net/socket.test.ts`, `client/net/tokenStore.test.ts`

**Interfaces:**
- Consumes: `ClientMessage`, `ServerMessage` from `shared/protocol.ts`; `ConnStatus` (Task 1).
- Produces:
  - `tokenStore.ts`: `interface TokenStore { get(): string | null; set(token: string): void; clear(): void }` and `localTokenStore(storage?: Pick<Storage, 'getItem' | 'setItem' | 'removeItem'>): TokenStore` (key `truco.token`; defaults to `localStorage`; swallows storage exceptions such as private mode and returns `null`).
  - `socket.ts`: `interface SocketOptions { url: string; tokens: TokenStore; WebSocketImpl?: typeof WebSocket; backoffMs?: (attempt: number) => number; onMessage(msg: ServerMessage): void; onStatus(status: ConnStatus): void }` and `class GameSocket { constructor(opts: SocketOptions); connect(): void; send(msg: ClientMessage): void; close(): void }`.
  - Behaviour: on open, if a token is stored send `{t:'rejoin', token}` first; on a `joined` message store the token; on `error` with `bad_token` clear the stored token; on unexpected close set status `'reconnecting'` and retry with backoff (default 500 ms doubling, capped at 5 s, with attempt reset on open); `close()` stops retries and sets `'closed'`; `send` while not open drops the message and returns without throwing; malformed server JSON is ignored.

- [ ] **Step 1: Failing tests** with a `FakeWebSocket` class injected as `WebSocketImpl` and a fake `backoffMs: () => 0` plus fake timers: rejoin sent first when a token exists and not sent when none; token stored after `joined`; `bad_token` clears it; unexpected close → status `reconnecting` then a new socket is opened and `rejoin` re-sent; attempts back off using the injected function; `close()` prevents reconnect; `send` before open does not throw; invalid JSON from the server does not call `onMessage`. `tokenStore`: round-trips; returns `null` when `getItem` throws.
- [ ] **Step 2: Run** `npx vitest run client/net`. Expected: FAIL.
- [ ] **Step 3: Implement** both files.
- [ ] **Step 4: Run** the same command and `npm run typecheck`. Expected: PASS.
